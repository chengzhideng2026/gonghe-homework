## 实际改动与边界

复用现有 ToolRegistry 的注册、Schema 校验、实际 ask 调度、收据和追踪。aggregate_documents 已有父单去重聚合；calculate 已有 Decimal 表达式，但二者不能直接从已读子表同时产生所有统计且避免数字转抄。现有收据保留身份和范围，但不保留完整子表，因此计算不能只依赖收据摘要。

新增 `detail_statistics.py` 和第九个工具 `summarize_details`。ask 在成功执行 get_document/get_documents 后，保存当前轮实际返回值、参数、工具版本和 io 时间证据的副本。工具参数只能引用这些真实调用 ID、子表字段、字段映射及精确行筛选，不能提交数字数组；外部传入聊天历史和旧轮摘要不会成为计算证据。

一次返回匹配行数、不同父单数，并按公司/币种/单位分别返回数量及行金额合计、单价极值、加权单价。加权单价明确为 `sum(qty*rate)/sum(qty)`，分子独立于行 amount 合计；Decimal ROUND_HALF_UP 保留两位，合计不舍入。空结果无极值/均价，零分母返回 null 和原因。缺失必需字段、无稳定行名、身份冲突、非有限数拒绝计算。相同子行身份去重，冲突值拒绝；相同数值但不同身份保留。部分读取只计算成功记录的小计，complete=false 并保留失败身份。

complete 仅指引用父单及行筛选的覆盖，不证明用户业务范围已穷尽。返回父单名称、字段映射、筛选、实际父单日期/docstatus/公司/币种观察及缓存时间；上游过滤和分页是否覆盖业务范围仍须核验。Sequential reads 不是事务快照。没有 DocType/物料/供应商/答案特例；未知 DocType 的通用读取保持原样。

新增复杂度是一个当前轮证据副本、一份字段映射和一个统计工具；增加内存占用和模型工具描述。为正确去重，必须有稳定子行身份。暂只接 get_document/get_documents，不接 list_documents 的子字段投影，不复用旧轮证据，不做单位或币种转换。新增工具没有解决模型可靠选择工具和引用真实调用 ID 的问题。

采购确认、幂等、权限、参考日期规则、请求预算和原工具行为均未改。没有新框架、运行时多 Agent 或其他平台功能。

## 真实失败路径与结论

D01：实验版没有调用 summarize_details，仍调用三次 calculate。少掉的两个 ERP 请求来自避免了原版错误聚合查询，不能归因于新统计工具。

D02：list_documents → get_documents，实际返回按供应商协议生成的长调用 ID；模型随后把 `call_2`、`call_1` 填入 source_call_ids，均不是当前轮保存的真实读取 ID。新工具在来源查找时拒绝，未进行 HTTP 或产生假证据；模型回退三次 calculate。一次 ask 内这两次失败都保留，不是评测重跑。原版则投影父单关联子字段，省掉逐父单读取，但也有两次错误聚合及一次不受支持的 round 表达式调用。完整原始路径见 [回答与证据](ANSWERS_AND_EVIDENCE.md)。

合计模型调用少1次、ERP请求少1次，但 usage 从79206升至115568、耗时从93.263升至97.239秒；样本只有两组，且新工具成功调用为0，不能证明性能收益或稳定性提升。离线确定性计算与严格来源校验有价值，但当前接入方式增加了工具选择、来源引用和父单读取成本。
