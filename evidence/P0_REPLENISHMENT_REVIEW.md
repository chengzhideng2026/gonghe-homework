# P0 补货口径与预览边界候选

追加基线：`ceb67ec90046c9316ce9a04c5c71dc6a3455e4be`，分支 `fix/targeted-business-robustness`。本轮只修改模型收到的通用补货规则和已有采购工具说明；没有增加工具或修改采购执行实现。

## 原失败定位

已核查 FNL-12 两轮用户原文、模型实际回答、调用参数、工具正文和完整收据。来源为独立评测 `run_baseline_supplement_20261018T135344_aeb63ef5/final_report.json`，SHA-256：`653c46242ca3780fc5e4d63374e3478b31d555c00ad2202cc2b326714d229304`。原文件及其他历史失败保留，未改冻结测试。

第一轮询问现货、在单数量和采购价格，并给出目标数量，但没有明确选择把尚未到货的订单抵扣现货目标。第二轮允许供应商留空，仅请求预览，明确禁止创建或确认 ERP 单据。

工具实际提供：

| 内容 | 已有证据 | 证据边界 |
|---|---|---|
| 物料、仓库、单位 | 精确过滤的 Bin 与 Item | 只覆盖该物料、仓库和快照 |
| 现货、在单、销售预留 | actual_qty、ordered_qty、reserved_qty | 未查询其他预留、预计库存或到货日期 |
| 历史采购价 | Item.last_purchase_rate | 不是当前供应商议价，未返回币种 |
| 供应商、公司及报价币种 | 未核实 | 用户要求 USD 不等于历史价格已证实为 USD |

两种缺口的 Decimal 计算均正确。错误路径是：第一轮将条件性的在途供给缺口追加解释为采购建议，第二轮直接沿用这个数，而不是明确目标口径。不是修复 `calculate` 的算术。

模型没有调用 `prepare_purchase_order`。缺供应商和明确报价币种确实不满足该工具的安全要求，这个拒绝调用本身合理；问题是把“不能创建可确认提案”扩大为“不能给任何预览”。用户允许的是缺字段、不可执行的初步方案，不能据此绕过供应商、报价和本位币校验。

审阅过程曾误展开含 Oracle 的案例文件，因此本轮不能声称是盲测。实现依据上述原问答和工具事实作通用规则修改，运行时代码没有写入题目数量、物料、供应商、单号或预期答案；新增用例使用不同数量与对象。这一过程偏差保留记录，不把它包装成独立验收。

## 最小修改与前后差异

- `agent.py`：在真实 `ask()` 的系统消息中加入有版本标记且不重复的补货规则，旧历史也会升级。区分实际现货、相关预留、在途和预计库存；未明确未来供给口径时以标注的现货缺口为主，未来供给单列并注明到货条件。跨轮沿用明确口径，不取最后提到的数字；准备可确认提案前澄清实质歧义。没有扩展查询或增加请求。
- 同一规则明确非执行性初步方案：列依据、假设和缺失字段；历史价不能冒充当前议价，预算币种只能作为明确未核实的条件假设。派生金额继续由已有 `calculate` 计算。初步方案没有 proposal_id、pending 状态或 `/confirm` 指令。
- `erp_tools.py`：只补充 `prepare_purchase_order` 描述，引导缺字段时提供初步方案。函数、参数结构、必需字段、Decimal 参数解析和校验不变。
- `tests/test_replenishment_boundaries.py`：8 项离线协议/状态回归，模型回复由脚本提供，调用真实 `ask()`、Decimal 计算和采购验证流程。
- `tests/test_turn_controls.py`：长历史测试夹具从 5,000 调整为 6,500 字节，为增长的不可裁剪系统规则及摘要留出空间，仍触发旧轮裁剪并核对历史摘要、工具配对及收据。运行时上下文配置、截止时间与 HTTP 请求预算均未调整。

小反例使用目标 80、现货 42、在途 13、销售预留 9：现货缺口 38；明确包括在途时条件缺口 25；以销售未预留库存为目标时可用量 33、缺口 47。不同口径分别使用计算工具，不能互换。该用例未声明所有预留已知。

## 剩余风险与停止条件

本修复依赖模型遵循精简规则，没有建立补货意图分类器、强制数量选择器或通用事实证明器。模型仍可能选错口径、漏限定语或重填错误计算参数；币种证据检查也不是金额来源的完整证明。新增规则增加少量上下文开销，极小预算仍可能装不下不可裁剪规则；不能把这次夹具通过解释为解决所有长上下文问题。

保持 `ceb67ec9` 可追溯，候选提交只正常推送到原分支、更新 PR #4，不合并 `main-v2`。停止开发，等待独立真实模型配对验证；当前不宣称 FNL-12 或隐藏题已通过。
